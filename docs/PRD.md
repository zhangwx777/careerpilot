# 产品需求文档（PRD）

> 本文档是产品目标、用户问题、功能范围和产品原则的权威来源。实现架构见 [`architecture.md`](architecture.md)，当前进度见 [`roadmap.md`](roadmap.md)，开发和运维细节不在本文件维护。

> 本文档是项目启动时的需求快照。开发过程中部分设定已迭代（例如公司与岗位改为创建投递时自动归档，不再要求先维护岗位库），**如与当前实现不一致，以实现和 `docs/开发文档.md` 为准**。

## 1. 产品定位

面向秋招、春招等校园招聘场景中个人求职者的**职航 CareerPilot**。不做自动投递，专注**信息聚合与决策辅助**：把分散在各平台的投递进度、时间线节点统一成一张求职地图，并针对目标岗位聚合结构化面经情报。

优先满足个人自用，体验完善后再考虑产品化。

## 2. 背景与问题

国内校园招聘与海外求职结构不同，海外工具（海投、ATS 优化、Easy Apply）的核心假设在国内并不完全成立。真正的痛点：

- **多平台进度分散**：网申官网 + 牛客 + 各公司小程序，状态更新不同步，全靠手动追。
- **时间线密集**：大厂 HC 8 月集中释放、10 月中旬基本关闭，窗口约 6 周，错过节点 = 错过一年。
- **笔试/面试冲突**：多场笔试撞车、临期节点无人提醒。
- **面经碎片化**：牛客/小红书/微信群到处是，无法针对"我投的这家这个岗"聚合。

市面现状：自动投递、简历 ATS 优化、通用模拟面试均已饱和且部分为国内伪需求。本产品切入未被做好的空白点。

## 3. 目标用户

- 主要：正在参加秋招、春招等校园招聘的应届生 / 实习生（当前为作者本人自用）。
- 特征：同时投递多家、需要统一管理进度与时间线、希望针对性准备面试。

## 4. 核心功能

### 4.1 方向 A：求职总览

| 功能 | 说明 | 优先级 |
|---|---|---|
| 投递记录管理 | 在投递时直接录入公司、岗位、JD 与备注；系统自动归档公司和岗位。允许同岗位多次投递，分别记录进度 | P0 |
| 状态机 | 已投递 → 测评 → 笔试 → AI面 → 一面 → 二面 → 三面 → HR面 → offer / 挂，可跳过不适用阶段 | P0 |
| 半自动解析 | 粘贴笔试/面试通知邮件、短信、网页文本，AI 抽取「公司+岗位+节点类型+时间」，人工确认后可新建本次投递或关联同一次既有投递，再写入时间线 | P0 |
| 截止时间推算 | 识别“3 个工作日内”等相对期限；开始时间缺失时默认当前时间，用户修改开始时间后自动更新截止时间 | P0 |
| 未提交内容保留 | 投递录入与通知确认中的未提交内容在当前浏览器暂存，切换页面后可恢复 | P0 |
| 作战地图 | 时间线的日历视图 + 列表视图 | P1 |
| 冲突检测 | 检测两场笔试/面试时间撞车、临期未处理节点并提醒 | P1 |

### 4.2 方向 B：定向面经情报

| 功能 | 说明 | 优先级 |
|---|---|---|
| 面经工作台 | 以公司+岗位聚合多次录入；录入时选择轮次，手动文本和截图优先，联网结果作为补充，并保留独立来源档案 | P0 |
| 面试洞察 | 跨轮次按语义考察方向统计多来源高频，选出核心问题并生成准备重点 | P0 |
| 截图识别 | 上传 PNG/JPEG/WebP 截图，由当前多模态模型提取文字，用户可编辑后分析 | P0 |
| 多源交叉验证 | 同一问题按不同来源合并，保留来源引用和冲突提示 | P0 |
| 结构化情报 | 输出面试流程、问题类别、参考回答、技术/项目/行为重点和准备事项；岗位级洞察另行输出高频考察方向 | P0 |
| 面经问答 | 围绕当前岗位资料持久问答，回答附来源引用 | P0 |
| 面试准备提醒 | 发现未来固定时间面试后，Agent 在开始前 24 小时自动写入时间线；无面试不推送 | P0 |
| 备战分析 | 上传简历，结合 JD + 面经情报生成匹配总结、优势、差距和准备行动清单 | P1 |

### 4.3 每日巡检（P2）

定时扫临期/冲突节点、对 pipeline 公司搜新面经、生成当日简报，避免重复提醒。

## 5. 关键产品原则

- **不做自动投递**：反爬/封号风险高、已饱和。
- **数据获取半自动**：粘贴文本或截图 → AI 解析，不自建爬虫（合规 + 稳定）。面经允许 AI 主动联网搜索公开内容作为补充。
- **人工在关键节点介入**：解析结果、情报冲突由用户确认，不盲目自动写库。
- **以投递为入口**：用户通常在投递时才掌握 JD 等信息，因此不要求先维护公司库或岗位库；它们仅作为系统内部归档结构。

## 6. 数据来源策略

- 投递进度、时间线：用户粘贴邮件/短信/网页文本，AI 解析。
- 面经情报：用户提供粘贴内容/截图并手动选择轮次，AI 主动联网搜索仅作补充；原始材料按公司+岗位沉淀，岗位洞察跨轮次分析全部来源。

面经工作台固定包含三个页内 Tab：

- **录入与进度**：选择材料轮次（测评、笔试、AI 面、一面、二面、三面、HR 面、多轮综合或未注明），录入文本或截图，查看识别和聚合进度。
- **面试洞察**：展示岗位级概览、跨轮次高频考察方向、核心问题、流程、准备重点和岗位问答。高频按独立材料来源计数，同一来源内重复出现只计一次；只有一个来源时不标记高频。
- **面经档案**：按当前岗位保存每份独立材料，支持轮次筛选、展开原文/截图识别文字/联网来源和删除。它承担证据追溯，不承担岗位级高频或准备重点分析。

材料确认写入后或删除后，会重新生成岗位洞察；洞察失败不影响原始材料保存，可通过 dossier rebuild 接口重试。面经问答由模型结合岗位资料和通用知识直接生成答案，不要求资料中已有标准答案。

## 7. 范围外 / 暂缓

- 定向模拟面试（红海，差异化需靠面经+简历驱动出题）：A+B 闭环跑通后再评估。
- 自动投递、简历 ATS 关键词优化。
- 多用户、账号体系、云端部署：产品化阶段再做。

## 8. 待定项

- 目标公司/岗位规模上限：待定。
- 面经数据源具体接入哪些站点：待定。
- 前端 UI 风格与交互细节：待定。
- 提醒渠道：当前仅写入站内时间线，不发送外部推送；后续如需扩展再单独评估。
