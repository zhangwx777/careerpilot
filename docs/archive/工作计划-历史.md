# 工作计划（历史归档）

> 本文档保留阶段性实施记录，不作为当前路线图。当前进度和验收标准见 [`../roadmap.md`](../roadmap.md)。

分 5 期，每期做完验证再进下一期。

## 设计原则

- **不做自动投递**：反爬/封号风险高、市面已饱和，价值存疑。专注信息聚合与决策辅助。
- **数据获取半自动**：粘贴邮件/短信/网页 → AI 解析，不自建爬虫（合规 + 稳定）。
- **LangGraph 是被需求逼出来的**：只在控制流本身绕不开图编排的地方用（并行 fan-out、条件循环、人工 interrupt），而非装饰。

## 暂缓项

- **定向模拟面试**：模拟面试是红海，差异化必须来自「面经 + 简历驱动出题」。等 A+B 闭环跑通后作为最后一期评估。
- **Docker 部署 / 云数据库**：个人本地阶段不做，产品化时启动。
- **数据库备份脚本**：需要多设备/换机时再加。

## 第一期：每日可执行求职工作台（进行中）

目标是把投递、时间线、面经洞察和备战分析串成“建议 → 行动 → 完成/跳过/延期”的闭环。

- 将 `PreparationTask` 扩展为可排期或不排期的统一准备行动，保存优先级、分析版本序号和延期时间；保留历史排期任务及时间线同步。
- 备战分析完成后自动物化所有 `PlannerAction`；通过 `(planner_session_id, action_index)` 幂等去重，并提供已完成分析的补生成接口。
- Dashboard 增加“今天先做”区域，按确定性规则展示最多 5 条待处理行动；不触发 LLM 或公开检索。
- 前端支持行动完成、跳过、延后到明天、打开岗位和返回分析历史；备战中心显示每条行动的实时状态。
- 增加数据库初始化迁移：任务排期字段可空，补充优先级、行动序号、延期时间和查询索引；不引入多用户或外部通知。

**验收**：同一分析重复打开不产生重复行动；未排期行动可在 Dashboard 查看并更新状态；延期行动在到期前隐藏、到期后恢复；已有排期任务仍能同步时间线；相关后端 API 测试、前端测试和生产构建通过。

## Agent 能力完善期（进行中）

本阶段目标是把“可运行的问答 Agent”收敛为可观测、可恢复、来源可校验的只读 Agent 系统：

- 统一 `AgentAnswerInternal` 回答契约和 `AgentRun/AgentStep` 运行轨迹；对外 API 增量返回资料不足、使用工具、回答模式和检索状态。
- 引入 Celery + Redis，面经问答、面经聚合、备战分析和岗位洞察重建进入持久队列；API 不再承担长耗时执行。Redis 不可用时 `/health` 明确降级，启动脚本直接提示。
- 根据问题确定性读取必要基础资料；Agent 只允许只读工具，服务端校验来源 ID、搜索失败声明和预算降级状态。
- Provider 测试同时记录 JSON、工具调用、流式和视觉能力。未验证工具能力的模型不能进入岗位问答 Agent；固定 Workflow 可继续使用普通文本模型。
- 面经公开资料改由受限研究 Agent 选择查询词，只能调用 AnySearch `search_public_intel`；服务端继续负责相关性、安全清洗、去重、抽取、Critic 和最终写库。
- 拆分 Notice/Intel/Planner Action/Planner Schedule/Chat/Critic/Insight/Runtime 提示词版本；历史任务保留创建时版本。

**当前验收重点**：Celery eager 模式和真实 Redis worker 均能创建、认领、完成与重试任务；同一消息不会重复执行；非法来源、空研究结果、预算超限和 Provider 工具不支持都有明确状态；前端显示生成中、失败、资料不足、检索失败和使用工具；真实 Anthropic 与第二家 Provider 另行执行 smoke test。
