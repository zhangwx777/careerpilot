## 1. 项目概览

“职航 CareerPilot”是面向秋招、春招等校园招聘场景的个人求职决策工作台，专注信息聚合与决策辅助（不做自动投递）。两大方向：A 求职总览、B 定向面经情报。详见 `docs/PRD.md`、`docs/开发文档.md`、`docs/工作计划.md`。

## 3. 第 1 期已交付内容

- 后端骨架：FastAPI + `/health`（含连库检查）。
- 数据库：PostgreSQL 业务表和 LangGraph checkpoint 表均由初始化脚本管理。业务表包括 company、position、application、timeline_node、parse_session、interview_intel、intel_session、intel_chat_message、resume_profile、planner_session、preparation_task、daily_briefing、reported_source；本地 PG 18 实例，数据库名 `qiuzhao`，使用专用低权限账号连接。
- 多模型 provider 层：LiteLLM 统一 Anthropic / OpenAI / DeepSeek / Qwen；Provider、API Key、Base URL 和默认模型只由设置页写入本地数据库。网页 API Key 使用 Fernet 密文保存，接口只返回掩码。
- 脚本：`scripts/init_db.py` 建表、`scripts/smoke_llm.py` 测模型连通。
- 文档：README + PRD + 开发文档 + 工作计划 + 本交接文档。

## 4. 环境状态

- Python 3.12，虚拟环境在 `backend/.venv`，启动器与依赖均已恢复。
- Node.js 已具备；前端依赖与脚本通过 Corepack + pnpm 管理。
- PostgreSQL 18 本地服务可达；业务表、解析/情报/Planner 会话表、每日简报表和 LangGraph checkpoint 表均由初始化脚本管理。
- `.env` 由使用者自行配置数据库连接等运行参数，不入库；模型 Provider 配置不写入 `.env`。
- 设置页是模型设置的唯一入口。首次保存时服务端自动生成 `.llm_config_secret`，删除某个 Provider 配置后不会回退到 `.env`。
- `qiuzhao_test` 为独立 PostgreSQL 测试库；通过 `TEST_DATABASE_URL` 使用。`python -m scripts.init_db --test` 会初始化业务表和 LangGraph checkpoint 表，测试代码拒绝回退到开发库。

## 5. 第 3 期已交付与验证

- `parse_session` 审计表、`timeline_node.ends_at` 和 `scheduled_at` 索引已创建；初始化脚本会幂等执行所需 DDL 并调用 `PostgresSaver.setup()`。
- 通知解析按任务快照调用用户选择的 provider，并要求 JSON 输出；公司名、岗位名、节点类型、起止时间、来源无法确定时保持 `null`，不补造。
- LangGraph 固定流为 `extract → interrupt → persist`：首次请求只停在待确认状态；用户以原 `thread_id` 确认后才恢复并写入一条时间线。确认、丢弃的相同终态请求幂等，互斥终态返回 409。
- 时间线支持分页、左闭右开的时间范围和状态筛选；待处理的笔试/面试按半开区间检测冲突，其他节点仅参与临期/逾期提示。前端已交付智能录入、列表和月历＋当日详情。
- 历史全量验证覆盖 CRUD、PostgreSQL HITL 集成、解析与冲突边界、面经图的反馈重抽取与补搜查询；真实 Qwen 已完成一次“解析—人工确认—时间线写入”端到端验证，临时业务数据随后清理。后续运行 PostgreSQL 集成测试必须先确认 `TEST_DATABASE_URL` 对独立测试库可连接，跳过不等于通过。
- 前端 TypeScript 构建检查和 Vite 生产构建通过；桌面浏览器已核验智能录入、时间线列表和月历切换。

## 6. 数据同步说明

- 代码通过 git 同步；数据库数据不入库，在本地 PG 实例中。
- 换机时：代码 `git clone`；`.env` 需重建；数据用 `pg_dump`/`psql` 手动导出导入，或后续改用云数据库（仅改 `.env` 连接串，代码不动）。

## 7. 第 5 期已交付与验证

- 简历以单条本地档案保存；支持上传 PDF/DOCX，服务只保存提取文字和文件名。备战分析快照简历、JD 和最近已确认面经，直接返回匹配总结、优势、差距与准备行动，不再自动排期。
- 面经工作台分为录入与进度、面试洞察、面经档案。录入时必须选择轮次；档案保留每份原文、每张截图的识别文字和联网来源，岗位洞察跨轮次按语义考察方向聚合，按独立来源计数，单来源不标记高频。问答由模型结合岗位资料和通用知识直接生成答案。
- 历史 `preparation_task` 及对应时间线节点保留，新的备战分析不会创建它们，也不会改写已有任务或投递状态。
- 每日简报应用启动会补跑当天，之后服务器存活期间每天上海时间 09:00 执行；手动运行同日幂等。它用 AnySearch 发现未结束投递的新增公开面经 URL，并持久化去重，不自动发起面经聚合。
- 新增备战分析、每日简报前端页面；时间线继续显示历史备战任务标题与说明，历史任务状态与时间线状态同步。
- 本轮验证包含简历上传/提取、投递阶段流转、面经结构化和前端构建；PostgreSQL 集成测试必须在配置 `TEST_DATABASE_URL` 后运行，未配置时跳过不算通过。

## 10. 最近使用反馈迭代

- 投递以直接输入公司、岗位和可选 JD 为入口。后端自动查找或创建内部 `company` / `position`，同岗位多次投递各自保留；公司库、岗位库不再是主导航页面。
- 智能录入默认创建本次投递；用户可在确属同一次投递时展开选择器关联已有投递。唯一匹配的已有投递只会预选，不会阻止新建。
- 解析到相对工作日截止期限时，确认页会依据开始时间推算结束时间；缺失开始时间时使用当前时间。新增投递和通知确认的未提交内容保存在当前浏览器的 `localStorage`，成功保存、确认或丢弃后清除。
- 根目录 `start.bat` 是推荐入口：它初始化数据库，为本次运行获取新的项目端口（优先 8000/5173），并尝试打开浏览器。自动打开失败不会停止服务；请以后端/前端启动时打印的实际 URL 为准。这样可避免代码更新后误复用旧进程。
- 设置页位于 `/settings`，可配置、测试、设为默认或删除四家 provider。解析、面经、备战和问答任务创建时固定 provider/model/Base URL/API Key 密文快照与 prompt 版本；修改默认值不会影响已创建任务。
- `app/llm/prompts.py` 集中维护版本化提示词，`app/llm/structured.py` 负责 JSON 清理、Pydantic 校验和一次有限修复；用户原文、JD、面经和联网内容都按不可信资料处理。
