## 3. 数据模型

## 4. 多模型 provider 层

### 设计
- `registry.py`：`PROVIDERS` 字典把 provider（anthropic/openai/deepseek/qwen）映射到 `{api_key, api_base, model}`，三项全部来自 `.env`，代码不预设任何默认值。base_url 留空则为 `None`（走 LiteLLM 官方默认）。
- `provider.py`：`chat(messages, provider, response_format=None)` 统一入口。调用时显式指定 provider（如 `"qwen"`），模型名/key/base_url 取自该厂商在 `.env` 的配置。调用前校验 key 与 model 是否已配，缺失则抛错；需要结构化输出时原样传递 LiteLLM 的 `response_format`。当前没有 `parse` / `reason` 到模型的自动路由。

### 模型命名
`.env` 中每家的 `*_MODEL` 用 LiteLLM 格式 `provider/model`，如 `deepseek/deepseek-chat`。

## 7. API 现状

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /health | 健康检查 + 连库检查 |
| GET/POST | /api/companies | 公司分页列表/新增；列表支持 `q` |
| GET/PATCH/DELETE | /api/companies/{id} | 公司详情/修改/删除 |
| GET/POST | /api/positions | 岗位分页列表/新增；支持 `q`、`company_id` |
| GET/PATCH/DELETE | /api/positions/{id} | 岗位详情/修改/删除 |
| GET/POST | /api/applications | 投递分页列表/新增；支持 `q`、状态、公司、岗位筛选 |
| GET/PATCH/DELETE | /api/applications/{id} | 投递详情/修改/删除 |
| PATCH | /api/applications/{id}/status | 状态向后流转或转“挂” |
| POST | /api/parse-sessions | 提交通知原文，运行至人工确认暂停点 |
| GET | /api/parse-sessions | 分页读取解析会话，支持 `status` |
| GET | /api/parse-sessions/{id} | 读取单个会话，供刷新后继续确认 |
| POST | /api/parse-sessions/{id}/confirm | 提交人工修正并恢复图，写入时间线 |
| POST | /api/parse-sessions/{id}/discard | 丢弃待确认会话，不写时间线 |
| GET | /api/timeline | 时间线列表；支持 `start`、`end`、`status`、分页 |
| PATCH | /api/timeline/{id}/status | 更新节点状态 |

所有列表使用 `page` / `page_size` 分页，`page_size` 最大 100。`offer` 和“挂”为终态；未结束状态可跳到任意后续阶段或转“挂”。删除公司/岗位依赖现有外键级联删除下属数据。

解析会话只有“待确认”时可确认或丢弃；相同终态操作幂等，互斥终态操作返回 409。确认必须绑定已有投递，AI 提取的公司和岗位仅用于精确匹配推荐，不能自动建数据。时间范围采用左闭右开 `[start, end)`。

前端以“求职作战台”为对外名称，包含投递台账、公司库、岗位库、智能录入和时间线页面，采用白色系界面与蓝色操作强调。智能录入以“原文—确认单”并排核对为核心：AI 只给候选，用户必须选择投递并确认；时间线提供列表和周一开始的月历，当日详情显示状态、冲突、临期和逾期提示。

## 8. LangGraph 使用规划（第 3 期起）

仅在控制流本身需要图编排处使用，非装饰：
- 半自动解析的人工介入：`START → extract → review_interrupt → persist → END`。`extract` 显式走 Qwen 结构化输出，未知字段为 `null`；`review_interrupt` 的第一项操作是 `interrupt()`；PostgreSQL checkpointer 让进程重启后仍可用同一 `thread_id` 恢复，`persist` 在事务中写时间线和会话状态。
- 面经聚合：并行 fan-out → 汇聚 → 冲突消解 → 置信度条件循环 → Reflection 自校正 → 冲突时 interrupt 人工裁决。
