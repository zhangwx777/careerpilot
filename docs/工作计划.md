# 工作计划

分 5 期，每期做完验证再进下一期。

## 设计原则

- **不做自动投递**：反爬/封号风险高、市面已饱和，价值存疑。专注信息聚合与决策辅助。
- **数据获取半自动**：粘贴邮件/短信/网页 → AI 解析，不自建爬虫（合规 + 稳定）。
- **LangGraph 是被需求逼出来的**：只在控制流本身绕不开图编排的地方用（并行 fan-out、条件循环、人工 interrupt），而非装饰。

## 第 1 期：项目骨架 + 数据模型 + 多模型 provider 层 ✅ 已完成

- 目录结构、`.env` 配置、pyproject 依赖
- PostgreSQL 5 张表：company / position / application / timeline_node / interview_intel
- LiteLLM 统一 Claude/OpenAI/DeepSeek/Qwen，调用方显式选择 provider
- FastAPI + `/health` 连库检查

**验证**：`/health` 返回 ok；建表成功；smoke test 无 key 时优雅跳过。

## 第 2 期：投递管理 CRUD + 前端多页面界面 ✅ 已完成

- 后端：company / position / application 的 CRUD API，列表支持分页、搜索和筛选
- 状态机流转接口：允许跳到后续阶段，任意未结束阶段可转“挂”，offer/挂为终态
- 前端：React + Vite + Radix Themes 多页面界面，包含投递台账、公司库、岗位库、新增/编辑投递

**验证**：4 个 CRUD 集成测试通过；真实 PostgreSQL 完成创建、查询、更新、状态推进和级联删除联调；前端 TypeScript 检查和 Vite 生产构建通过；桌面及 390px 移动视口通过浏览器检查。

## 第 3 期：半自动解析 + HITL + 时间线/冲突检测 ✅ 已完成

- LangGraph 图：粘贴文本 → Qwen 解析结构化节点 → `interrupt()` 暂停等人工确认 → 原 `thread_id` 恢复写库
- Postgres checkpointer 持久化图状态；进程重启后仍能继续待确认会话
- `parse_session` 保存原文、AI 结果、人工确认结果、状态和错误；确认必须选择已有投递
- 时间线：列表 + 周一开始的月历与当日详情；冲突检测（待处理笔试/面试撞车）、临期与逾期提示

**验证**：23 项后端测试通过；真实 Qwen 样例完成解析、人工确认、时间线写入；前端 TypeScript 检查、Vite 生产构建和桌面浏览器检查通过。

## 第 4 期：面经聚合图（含金量核心）✅ 已完成

- AnySearch MCP 搜索（最多 5 条）/ 用户粘贴内容
- 汇聚 + 冲突消解：同一维度多说法按时间新旧 + 来源数量加权
- 置信度评分：低于阈值回搜索节点补充（条件循环）
- Reflection 自校正：critic 节点检查是否有编造/遗漏，不合格带批评意见重做（有环图）
- 仍冲突 → interrupt 交人工裁决

**验证**：AnySearch 真实返回中文面经及 URL；真实 PostgreSQL 图测试验证 interrupt、恢复、反馈重抽取和唯一写库；全量后端 28 项通过且 0 skipped；前端 TypeScript 与 Vite 生产构建通过。

## 第 5 期：备战 Planner + 每日巡检

- Planner：简历 + JD + 面经情报 → 能力差距分析 + 分解到日的任务，自动写回时间线（避开已有冲突）
- 每日巡检：定时扫临期/冲突节点、对 pipeline 公司搜新面经、生成当日简报（记住已报过的避免重复）

**验证**：情报能转成任务写回时间线；能出当日简报。

## 暂缓项

- **定向模拟面试**：模拟面试是红海，差异化必须来自「面经 + 简历驱动出题」。等 A+B 闭环跑通后作为最后一期评估。
- **Docker 部署 / 云数据库**：个人本地阶段不做，产品化时启动。
- **数据库备份脚本**：需要多设备/换机时再加。
