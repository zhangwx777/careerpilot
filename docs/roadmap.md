# 当前路线图

本文档是项目当前进度、下一步工作和验收标准的唯一权威来源。

## 已完成能力

- 投递、公司、岗位和时间线管理；阶段推进、临期/逾期和冲突检测。
- 投递台账保留完整阶段节点，当前节点由「推进」控件驱动，支持在任意阶段之间调整以适配非线性流程。
- 求职总览按投递分布、关注指标和「接下来」时间流组织，待练习行动与求职节点在同一条流中排序。
- 通知文本结构化解析、人工确认、可恢复会话和幂等写入。
- 面经文字/截图录入、公开检索补充、跨轮次洞察、冲突裁决和资料档案。
- 简历上传、岗位备战分析、准备行动和每日简报。
- 准备行动的独立练习页：生成参考答案、录入自答并返回岗位定制点评。
- 岗位级只读问答 Agent、来源校验、预算护栏、运行记录和 Celery 后台任务。
- 网页模型设置、四家 Provider 配置、加密密钥存储和任务配置快照。
- 面经、备战、简报和图片识别四个角色可分别指定 Provider，空映射回退全局默认。
- Windows 桌面打包与安装器（Inno Setup 标准安装包和免安装便携包）。

## 当前进行中

### 每日可执行求职工作台

状态：进行中。

目标：把投递、时间线、面经洞察和备战分析串成“建议 → 行动 → 完成/跳过/延期”的闭环。

验收标准：同一分析重复打开不生成重复行动；未排期行动可在 Dashboard 更新状态；延期行动按到期时间恢复；历史排期任务继续同步时间线；后端测试、前端测试和生产构建通过。

### Agent 能力完善

状态：基础能力已落地，发布前验证进行中。

目标：验证 Celery 真实 worker 的认领、重试和幂等行为，并完成 Anthropic 与第二家 Provider 的 JSON、stream、tool smoke test。

阻塞条件：真实 Redis worker、独立 PostgreSQL 升级演练或第二 Provider 无法验证时，不扩大 Agent 工具范围，不引入 Multi-Agent。

## 下一阶段候选项

- 依据真实使用反馈评估“面经 + 简历驱动的定向模拟面试”。
- 在需要多设备使用时评估数据库备份脚本和云数据库支持。
- 只有在多用户需求明确后再评估账号、权限和云端部署。

## 暂缓项

- 自动投递、邮件接入和外部推送；
- 通用公司研究 Agent、简历 Agent 和 Multi-Agent 拆分；
- 向量数据库；
- Docker/云部署和多用户架构。

## 最近验证

当前验证以本机重新执行为准：后端 pytest、前端 `pnpm test`、前端 `pnpm build`，以及配置 `TEST_DATABASE_URL` 后的 PostgreSQL/LangGraph 集成测试。未配置独立测试库导致的 skip 不得写成“全部通过”。
